# Komari Daily & Weekly Reports

Komari 监控日报与周报插件，定时汇总服务器运行情况，并通过现有 Telegram 通知发送报告。

## 1、功能介绍

- **采集内容**：节点上传/下载流量、Ping 延迟与丢包、在线率，以及上下线、性能告警（CPU、内存、磁盘、负载）、到期提醒和续费事件。事件记录需配置下方的通知转发。
- **通知方式**：复用 Komari 已有的 Telegram 通知发送日报和周报，保留原有即时告警。日报和周报可分别启停，自定义发送时间、周报星期和时区。
- **管理功能**：报告预览、手动发送、历史补发、发送记录查询和备份导出。无异常或数据不足时也会按计划生成报告，数据不足会在报告中提示。

| 报告 | 默认发送频率（北京时间） | 统计范围 |
| --- | --- | --- |
| 日报 | 每天 23:59 | 当天 00:00 至发送时点 |
| 周报 | 每周一 09:00 | 上一完整自然周（周一至周日） |

例如：11 月 12 日 23:59 发送 **11 月 12 日**的日报，统计当天 00:00 至 23:59 的数据。修改发送时间后，日报也统计当天截至发送时点的数据。

**支持版本**：Komari **1.6.1**；更高版本请先确认兼容性。

## 2、如何安装

### 安装步骤

1. 从 [Releases](https://github.com/zhfk/komari-usage-report-plugins/releases) 下载 `komari-daily-weekly-reports-<版本号>.zip`，不要使用 GitHub 自动生成的 Source code 压缩包。
2. 在 Komari 后台的插件管理中上传 ZIP，按提示批准 `node`、`allowSystemRPC` 和 `allowRoutes` 权限。
3. 在插件的**托管配置**中设置发送计划、参与节点和通知转发，具体见下文。
4. 启用插件，打开**监控日报与周报**管理页，完成测试通知和报告发送检查。

### 插件配置

配置在托管配置表单中修改，保存后在下一次检查时生效。发送时间使用 `HH:mm`；周报星期使用 0–6，0 为周日、1 为周一。

| 配置项 | 默认值 | 配置说明 |
| --- | --- | --- |
| 报告时区 | `Asia/Shanghai` | 北京时间；也可用 `UTC`，其他时区需宿主支持 |
| 参与节点 UUID | 留空 | 全部可见节点；指定多个节点时用逗号分隔 |
| 包含隐藏节点 | 关闭 | 需要统计隐藏节点时再开启 |
| 报告内容 | 全部开启 | 按需开关流量、延迟、在线率、事件、周期对比、周报排名和运行总结 |
| 平均延迟警告阈值 | 200 ms | 按需调整 |
| 单次延迟告警阈值 | 300 ms | 按需调整 |
| 丢包率警告阈值 | 5% | 按需调整 |
| 自动追补天数 | 3 天 | 可设 0–31；设为 0 关闭历史追补 |
| 事件与在线观察保留天数 | 180 天 | 可设 90–730 天 |
| 日报聚合与发送记录保留天数 | 180 天 | 可设 14–730 天 |

节点默认按名称排序，也可将排序设为 `traffic`（流量）或 `uptime`（在线率）；按名称排序填 `name`。每份报告默认最多展示 50 条事件，每段消息默认 2800 字符；通知模板较长时可适当调低。

### Telegram 与事件转发配置

插件复用 Komari 已有的通知配置，无需重复填写 Bot Token 或 Chat ID。请配置通知转发示例，让现有脚本能够处理日报、周报并采集监控事件。

1. 在 Komari 中启用通知、选择 Telegram 渠道，确认原有测试通知可以收到。
2. 备份现有 JavaScript 通知脚本。脚本需在同一作用域提供 `sendMessage(message, title)`；函数名不同，请调整示例中的对应调用。
3. 在插件配置的 `eventSecret` 中填写随机生成的至少 32 字符密钥。
4. 将 [notification-forwarder.js](examples/notification-forwarder.js) **追加到现有通知脚本末尾**，并修改示例顶部的两个值：

   | 设置 | 填写内容 |
   | --- | --- |
   | `REPORT_PLUGIN_URL` | 例如 `https://komari.example.com/api/plugins/komari-daily-weekly-reports/events`；替换为 Komari 可访问的 HTTPS 域名，保留完整路径 |
   | `REPORT_PLUGIN_SECRET` | 与插件配置的 `eventSecret` 相同；请勿公开密钥 |

5. 开启插件配置中的 `eventForwarding`（已安装并启用事件转发脚本），保存设置后进行测试。

Telegram 发送代码应使用 HTML `parse_mode`，不要对报告正文再次转义。通知模板建议只保留 `{{message}}`，或使用简短的前后缀。需要恢复原通知脚本时，移除追加部分并关闭 `eventForwarding`。

### 如何发送测试

在**监控日报与周报**管理页中完成以下检查：

1. 点击**测试通知**，到 Telegram 确认收到消息。
2. 选择日报或周报及历史日期，点击**预览**。日报统计所选日期，周报统计该日期所在的周一至周日；只能选择已经结束的周期。
3. 分别**手动发送**一份日报和周报，检查日期、节点范围、分页及 HTML 显示。测试通知成功后，仍需验证实际报告。
4. 将发送时间临时设为稍后的时间，验证尚未自动发送过的周期是否按时收到，随后恢复配置。已自动发送的周期不会因改时间而再次自动发送。
5. 确认原有即时告警仍能收到，并在对应周期结束后的报告中检查事件记录。

遇到问题时，在管理页查看**插件运行状态**、最近日志和**最近发送记录**：

- `accepted` 仅表示 Komari 接受发送请求，请到 Telegram 核实；未收到时检查通知开关、渠道和通知脚本。
- `unknown` 或部分分页失败时，先核实已收到的内容，再点击“重试未完成分页”，避免重复发送。
- 数据不足时检查节点、Ping 任务和历史数据。在线率为观察估算，安装前的在线历史无法还原；未采集到事件也不代表没有异常。

手动发送与自动计划分别记录，手动发送过的周期仍可能按自动计划发送。升级前请下载备份并备份插件数据目录；卸载会删除插件数据，若要暂停并保留历史，请禁用插件。

## 3、关于二次开发

### 下载源码

准备 **Node.js 24 或以上版本**、npm 和 Git；打包还需要 **Python 3**。

```sh
git clone https://github.com/zhfk/komari-usage-report-plugins.git
cd komari-usage-report-plugins
npm ci --ignore-scripts
```

### 启动与测试

本项目通过 **Komari 加载运行**。修改源码后，先进行本地检查和测试：

```sh
npm run check
npm test
```

再按下一节生成安装包，上传到 Komari 插件管理并启用，通过“监控日报与周报”管理页预览、发送报告，验证修改效果。

### 打包

在仓库根目录运行：

```sh
npm run package
```

该命令会自动执行检查、测试、构建和打包。安装 ZIP 与校验文件 `SHA256SUMS` 输出到 `artifacts/`，上传其中的 ZIP 即可安装。
