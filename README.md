# Komari Daily & Weekly Reports

Komari 监控日报与周报插件，定时汇总服务器运行情况，通过 Telegram 通知渠道发送报告。

## 1、功能介绍

- **监控内容**：节点上传/下载流量、Ping 延迟与丢包、在线率；配置事件转发后，还可汇总上下线、性能告警、到期提醒和续费事件。
- **通知频率**：日报和周报可分别启停，自定义发送时间、周报星期和时区。无异常或数据不足时也会按计划生成报告。
- **配置与发送**：在插件配置页下方直接测试通知、发送今日日报、预览和补发历史报告、查看发送记录及下载备份。

| 报告 | 默认发送频率（北京时间） | 统计范围 |
| --- | --- | --- |
| 日报 | 每天 23:59 | 当天 00:00 至发送时点 |
| 周报 | 每周一 09:00 | 上一完整自然周（周一至周日） |
| 发送今日日报 | 点击按钮立即发送 | 今天 00:00 至当前时间，按配置时区计算 |

例如：11 月 12 日 23:59 发送 11 月 12 日的日报；当天 15:00 点击“发送今日日报”，统计范围为当天 00:00 至 15:00。

**支持版本**：Komari **1.6.1**；更高版本请先确认兼容性。

## 2、如何安装

### 前置依赖：Telegram 通知插件

先安装并配置 **Telegram 通知**（`telegram-notification-plugin`），再安装本插件。

1. 在 Komari 的**插件市场**中安装并启用“Telegram 通知”；也可从 [通知插件 Releases](https://github.com/Akizon77/komari-notification-plugins/releases) 下载 `telegram-notification-plugin.zip`，上传到插件管理后启用。
2. 打开后台的**通知 → 通知渠道**，开启通知，选择 **Telegram**。
3. 在该渠道中填写 **Telegram Bot Token** 和 **Chat ID**；使用群组话题时，按需填写消息话题 ID。保存配置。
4. 点击该页面的**测试通知**，确认 Telegram 实际收到消息。通知模板建议使用 `{{message}}`，或保留简短的前后缀。

| 插件 | 作用 | 配置内容 |
| --- | --- | --- |
| Telegram 通知 | 将 Komari 通知投递到 Telegram | 在“通知 → 通知渠道”填写 Bot Token、Chat ID |
| Komari 日报与周报 | 采集指标、生成报告、定时或手动发报 | 在本插件配置中设置时间、节点和报告内容 |

本插件复用已选中的通知渠道，无需重复填写 TG 凭据。日报、周报和 Komari 原有通知使用同一渠道；请保持两个插件均已启用。

### 安装日报与周报插件

1. 从本仓库 [Releases](https://github.com/zhfk/komari-usage-report-plugins/releases) 下载 `komari-daily-weekly-reports-<版本号>.zip`，不要使用 GitHub 自动生成的 Source code 压缩包。
2. 在 Komari 后台的插件管理中上传 ZIP，按提示批准 `node`、`allowSystemRPC` 和 `allowRoutes` 权限。
3. 打开本插件的**配置**，检查发送计划、报告时区和参与节点。如果只想先手动测试，可先关闭“启用日报”和“启用周报”。
4. 保存配置并启用插件。回到同一配置页，下拉到**发送与记录**面板即可操作，无需另外打开管理页面。

历史追补默认关闭。需要补发停机期间漏掉的报告时，再设置“自动追补天数”。升级会保留已保存的设置；如原值仍为 3，可手动改为 0 关闭追补。

### 插件配置

在上方配置表单中修改并保存，再使用下方发送按钮。发送时间使用 `HH:mm`；周报星期使用 0–6，0 为周日、1 为周一。

| 配置项 | 默认值 | 配置说明 |
| --- | --- | --- |
| 报告时区 | `Asia/Shanghai` | 北京时间；也可用 `UTC`，其他时区需宿主支持 |
| 参与节点 UUID | 留空 | 全部可见节点；指定多个节点时用逗号分隔 |
| 包含隐藏节点 | 关闭 | 需要统计隐藏节点时再开启 |
| 报告内容 | 全部开启 | 按需开关流量、延迟、在线率、事件、周期对比、周报排名和运行总结 |
| 平均延迟警告阈值 | 200 ms | 按需调整 |
| 单次延迟告警阈值 | 300 ms | 按需调整 |
| 丢包率警告阈值 | 5% | 按需调整 |
| 自动追补天数 | 0 天 | 默认不补发历史报告；可设 0–31 |
| 事件与在线观察保留天数 | 180 天 | 可设 90–730 天 |
| 日报聚合与发送记录保留天数 | 180 天 | 可设 14–730 天 |

节点默认按名称排序，也可设为 `traffic`（流量）或 `uptime`（在线率）；按名称排序填 `name`。每份报告默认最多展示 50 条事件，每段消息默认 2800 字符。

### 实时发送与测试

操作入口统一在本插件**配置页下方的“发送与记录”面板**，不提供独立的插件页面或页面访问 URL。

1. **测试通知**：点击后，到 Telegram 确认收到消息。
2. **发送今日日报**：直接点击即可，无需选择历史日期或报告类型。每次都会重新统计今天 00:00 至当前时间的数据。
3. **预览与历史补发**：选择日报或周报及已结束的历史日期，先预览，再手动发送。周报统计所选日期所在的完整自然周。
4. **检查定时发送**：开启日报或周报，将发送时间设为稍后的时间，检查尚未自动发送过的周期是否按时收到，随后恢复配置。

手动发送与自动计划分别记录，点击“发送今日日报”后，晚上的自动日报仍按原计划发送。

遇到问题时，查看面板中的运行状态、最近日志和发送记录：

- `accepted` 表示 Komari 接受了请求，实际送达请到 Telegram 核实；未收到时检查通知开关、渠道选择和 Telegram 通知插件。
- `unknown` 或只收到部分分页时，先核实已收到的内容，再使用“重试未完成分页”，避免重复发送。
- 数据不足时检查节点、Ping 任务和历史数据。在线率为观察估算，安装前的在线历史无法还原。

### 可选：监控事件记录

Telegram 通知插件负责消息投递，不会自动把上下线、告警、到期或续费历史交给本插件。仅安装上述两个插件即可发送指标日报和周报；需要事件列表时，另行配置 [事件转发](docs/event-forwarding.md)。未配置转发时，报告会提示事件历史不可用，不能将没有记录理解为没有异常。

升级前请在面板下载备份，并备份插件数据目录；上传新 ZIP 后重新启用。若要暂停并保留历史，请禁用插件，卸载会删除插件数据。

## 3、关于二次开发

### 下载源码

准备 **Node.js 24 或以上版本**、npm 和 Git；打包还需要 **Python 3**。

```sh
git clone https://github.com/zhfk/komari-usage-report-plugins.git
cd komari-usage-report-plugins
npm ci --ignore-scripts
```

### 启动与测试

本项目通过 **Komari 加载运行**。修改源码后，在仓库根目录执行：

```sh
npm run check
npm test
```

再生成安装包，上传到 Komari 插件管理并启用，在配置页中预览、发送报告，验证修改效果。

### 打包

```sh
npm run package
```

该命令会执行检查、测试、构建和打包。安装 ZIP 与校验文件 `SHA256SUMS` 输出到 `artifacts/`，上传其中的 ZIP 即可安装。
